RTL and mixed text

RTL and mixed text

Keep Uyghur text, English technical values, keyboard behavior and map orientation clear.

On this page

Declare language and direction

<html lang="ug" dir="rtl">
<body class="ug-ui">...</body>
</html>

Language and direction are separate properties. Right alignment alone does not define RTL semantics. An English page can contain Uyghur sections with their own lang and dir. Use dir=auto when a user's input direction is unknown; use an explicit direction for known technical values.

Isolate addresses and versions

<p>بوغچا: <bdi dir="ltr" lang="en">@uyghurcommunity/ui</bdi></p>
<p>نەشر: <bdi dir="ltr">0.4.0</bdi></p>
<input type="email" aria-label="ئېلخەت" dir="ltr">
<textarea aria-label="مەزمۇن" dir="auto"></textarea>

Bidi isolation prevents punctuation in a URL, version or package name from affecting the surrounding sentence. Preserve the original data; solve display direction with HTML containers before altering the stored text.

Use logical CSS

.panel {padding-inline:1.25rem;margin-inline:auto;border-inline-start:3px solid var(--ug-blue);text-align:start;max-inline-size:48rem;}

Logical properties follow the writing direction and avoid a second set of left/right layout rules. Test real content in both directions, especially labels, dropdown placement and data-table headers. Keep native range controls explicitly LTR when their displayed minimum-to-maximum comparison needs a stable direction.

Keyboard and geographic direction

Tabs derive horizontal arrow behavior from the tablist direction; vertical tabs use Up/Down. Choose directional icons for the intended action because SVGs do not mirror automatically. A flag and geographic map retain their authored orientation, independent of the page's reading direction.

Preview text cleanup

Do not remove every format or joining character to repair a visual issue. Some affect shaping or meaning. The writing controller's preview, apply and undo steps make changes inspectable. Review a cleanup against the original, and validate separately. A transformation applied to a field is not a substitute for correct labels, direction or server-side validation.
